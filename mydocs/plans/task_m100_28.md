# Task M100 #28 수행 계획서: 리눅스 드래그 블록 선택/자동 스크롤 오류 분석 및 수정

## 1. 개요 및 배경
- **문제 현상**: 리눅스 Tauri/WebKitGTK 환경에서 최신 릴리즈 버전을 설치하여 실행 시, 글자를 입력하고 위에서 아래로 마우스 드래그 블록을 설정할 때 선택 갱신이 끊기거나 작동하지 않는 현상 발생. 아래에서 위로 드래그할 때는 일부 동작하나 마우스를 비정상적으로 멀리 움직여야 함.
- **주요 원인 파악 (사용자 보고 및 코드 사전 조사 결과)**:
  1. **드래그 선택 이벤트 바인딩 범위의 한계**: `input-handler.ts`에서 `mousemove` 이벤트가 에디터 컨테이너(`#scroll-container`)에만 국한되어 등록됨. 브라우저 창 바깥이나 컨테이너 경계를 벗어나는 순간 리눅스 WebKitGTK 환경에서 `mousemove` 이벤트 발생이 중단되어 선택 블록 갱신이 멈춤 (`setPointerCapture` 부재).
  2. **가장자리 자동 스크롤(Edge Auto-scrolling) 부재**: 마우스가 뷰포트 상/하단 가장자리를 벗어난 상태로 드래그를 유지할 때 화면이 자동으로 스크롤되며 선택 영역을 확장하는 텍스트 에디터의 필수 로직이 `input-handler-mouse.ts`의 드래그 루프에 존재하지 않음. 캐럿 이동 후의 화면 보정 로직만 존재함.
  3. **E2E 테스트 커버리지 부족**: 기존 `selection-visual.test.mjs` 등 E2E 테스트가 `Ctrl+A`에 치중되어 있으며, 실제 상/하 마우스 드래그 동작 및 컨테이너 이탈, 가장자리 자동 스크롤에 대한 자동화된 검증이 없음.

## 2. 목표
- 전수 조사(Ouroboros 패턴 및 소프트웨어 공학의 심층 디버깅 기법 적용)를 통해 `input-handler`, `input-handler-mouse` 코드 내부의 드래그 이벤트 생명주기 및 좌표 처리 로직을 한 줄, 한 글자 단위로 전수 분석.
- 리눅스 환경에서도 브라우저 외곽까지 포인터를 추적하도록 `PointerEvent` 캡처(`setPointerCapture`) 또는 글로벌 `document` 이벤트 바인딩으로 드래그 이벤트 아키텍처 리팩터링.
- 드래그 중 자동 스크롤 타이머(RAF 기반)를 구축하여 워드프로세서의 자연스러운 위/아래 가장자리 스크롤링 경험 구현.
- Puppeteer 기반 E2E 테스트 케이스 확충(실제 마우스 궤적 시뮬레이션).

## 3. 세부 작업 방향
1. **코드 전수 조사 및 분석**:
   - `rhwp-studio/src/engine/input-handler.ts`, `input-handler-mouse.ts` 전체 리뷰.
   - 마우스 다운(`mousedown`) -> 이동(`mousemove`) -> 업(`mouseup`) 간의 상태 전이 무결성 검증.
2. **드래그 캡처 시스템 재설계 (Pointer Events 도입 고려)**:
   - 기존 `mousedown`/`mousemove`/`mouseup`을 `pointerdown`/`pointermove`/`pointerup`으로 마이그레이션하거나 드래그(`isDragging`) 상태 진입 시 `document` 레벨에 전역 이벤트를 위임하는 구조 적용.
3. **가장자리 자동 스크롤(Edge Auto-scroll) 루프 구현**:
   - 드래그 중인 포인터 좌표가 뷰포트의 상/하 가장자리 임계값(Threshold)에 도달할 시, 이벤트가 없어도 `requestAnimationFrame` 루프를 통해 `VirtualScroll`의 스크롤을 지속 증감시키는 엔진 구현.
4. **E2E 테스트 작성**:
   - `e2e/selection-drag.test.mjs` 신규 작성하여, 마우스를 에디터 밖으로 끌어냈을 때 스크롤이 자동으로 움직이고 텍스트가 블록 처리되는지 검증.
