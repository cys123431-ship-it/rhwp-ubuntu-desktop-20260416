## 현황 분석

### 사용자 제보

- 리눅스 로컬 설치본에서 프로그램을 켜고 글자를 입력한 뒤 위에서 아래로 블록 선택이 잘 되지 않는다.
- 밑에서 위로 블록 선택은 되지만 마우스를 매우 멀리 움직여야 한다.
- 최신 버전을 설치했다고 인식했으나 실제 설치/릴리스 버전 확인이 필요하다.

### 검토로 확인한 문제

| 항목 | 확인 내용 |
|------|-----------|
| 드래그 이벤트 | `mousedown`/`mousemove`가 `#scroll-container`에만 등록되어 있고 드래그 중 전역 `mousemove` 또는 pointer capture가 없다. |
| 드래그 종료 | `mouseup`만 `document`에 1회 등록되어 있어 이동 이벤트와 종료 이벤트의 수신 범위가 불일치한다. |
| 자동 스크롤 | 드래그 중 상하 가장자리에서 선택 범위를 계속 확장하는 auto-scroll 루프가 없다. |
| 최신 설치 | 원격 최신 태그는 `v0.1.12`이나 로컬 dpkg 설치본은 `0.1.11`이다. |
| 버전 파일 | `rhwp-desktop/package.json`은 `0.1.12`로 수정되어 있으나 `tauri.conf.json`/`Cargo.toml`은 `0.1.11`이다. |
| 테스트 오염 | `cargo test`가 `samples/re-*.hwp` 90개를 수정 상태로 남긴다. |
| 포맷 | `cargo fmt --check`가 실패한다. |
| E2E | 기존 선택 E2E는 `Ctrl+A` 중심이며 실제 위→아래/아래→위 마우스 드래그 선택을 검증하지 않는다. |

### 원인 가설

1. Tauri Linux WebKitGTK에서 마우스 드래그가 편집 영역 경계를 벗어나면 `#scroll-container`에 묶인 `mousemove`가 끊긴다.
2. 선택 드래그 중 자동 스크롤이 없어, 반대 방향 또는 문서 가장자리 방향 선택에서 사용자가 마우스를 비정상적으로 멀리 움직여야 한다.
3. 로컬 설치본이 `0.1.11`이라 `v0.1.12` 태그의 상태와 사용자가 실행한 프로그램이 일치하지 않을 수 있다.

## 리스크와 대응

| 리스크 | 대응 |
|--------|------|
| Pointer Events 전환이 기존 그림/표 리사이즈 드래그와 충돌 | 우선 텍스트 선택 드래그에 한정된 전역 mousemove/pointer capture 보강으로 범위를 제한한다. |
| auto-scroll이 너무 빠르게 동작 | 가장자리 임계값과 최대 속도를 제한하고 requestAnimationFrame 기반으로 구현한다. |
| 테스트 생성 샘플이 의도된 개발 도구일 수 있음 | 기본 `cargo test`에서는 쓰지 않게 하고, 수동 재생성 경로는 별도 플래그/ignored 테스트로 남긴다. |
| 로컬 설치에 시스템 권한이 필요 | 빌드 산출물 생성 후 가능한 경우 `apt`/`dpkg` 설치를 수행하고, 실패 시 산출물 경로와 실패 사유를 보고한다. |
